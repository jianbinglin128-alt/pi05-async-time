# 自适应 k 调度器

每次固定预测 H=10 个动作，固定执行 E=10 个动作（任务提前终止除外）。运行时拒绝其他执行长度；模型声明和每次实际返回的动作长度均须为 10。在当前块执行了 E-k 个动作后，用当前观测和剩余 k 个动作作为上下文请求下一块。模型预测上下文之后的动作，因此上下文必须执行完再交接，新预测从第 0 个动作开始使用。

## 时间预算

最近 32 次完整请求耗时的 P95 记为 L，最近 128 次单步执行耗时的 P20 记为 d。请求耗时覆盖请求准备、后台排队、模型推理、通信和输出校验；执行耗时仅包含 env.step。

```text
budget = L + max(0.002 seconds, 0.05 * L)
k_raw = min { k in candidates : k * d >= budget }
```

默认候选集合为 2..9，初始 k=4。至少收集 3 次请求和 8 次动作计时后开始自适应。选择最小可行 k，使请求尽量晚发，同时预留预计足够的执行窗口。

## 稳定性与交接

- 每块开始时选择并冻结 k。
- 需要更大的 k 时立即增大；连续 3 块允许减小时降低一档。
- 最多保留一个在途请求。结果提前返回则缓冲；结果迟到则在边界等待。
- 无可行候选值时选择最大 k，并记录不可行状态。
- 终止回合后排空在途请求，不把终止后的动作提交给环境。

训练支持的上下文长度为 0..9，默认候选不超出该范围。经验分位数及安全余量不能保证实时覆盖或任务成功率；实际覆盖通过动作就绪时刻和上下文执行结束时刻计算。

## 参考与验证

时间预算规则参考 [ActECC IV-B](https://arxiv.org/html/2603.07949v3#S4.SS2) 的最晚可行请求思想。这里针对 Future 动作上下文模型实现；未核实到该论文的官方实现仓库。

测试和实际 LIBERO 功能验证范围见 [README](../README.md)。固定 k 对照通过评估入口的 `--fixed-k` 参数运行，使用相同模型权重与执行长度。
