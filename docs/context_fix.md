# JAX Future 动作上下文修复

初始提交 `8c92507` 的客户端和预处理已经传递动作上下文，但 JAX `Pi0` 没有读取它。加载器默认裁掉检查点的额外参数，因此程序能够运行，仍不能证明计算图匹配训练架构。此问题影响旧版固定 k 与自动 k 两组实验。

## 修复内容

- 恢复 `action_context_in_proj`，与 Future 训练架构使用相同的参数名称和维度。
- 将最多 9 个上下文 token 放在生成动作 token 之前；上下文块内部双向注意，生成动作可读取有效上下文，上下文不能读取生成动作。
- 使用上下文 mask 屏蔽补齐槽位，补齐输入规格，拒绝缺失或错误形状的上下文。
- Future 服务使用严格 JAX 参数树加载，缺失参数、额外参数或维度不匹配均报错。
- 服务端声明 `context_conditioning=jax_action_context_v1` 和严格加载状态，新评估客户端拒绝旧服务。

权重、10 次 flow 步、H/E、k 候选范围、分位数、安全余量、滞回及不可行时选择最大 k 的规则保持原设置，以便单独验证架构修复。预算不足时仍可能长期使用 k=9；此修复不保证覆盖全部推理耗时，也不保证任务成功率。

## 验证

`bash scripts/run_time.sh test 0` 运行 22 项 CPU 测试。新增网络测试使用真实 JAX Transformer 和小型视觉编码器，并在随机权重测试夹具中打开初始为零的 AdaRMS 注意力残差门；生产模型和检查点不做这种修改。

`bash scripts/run_time.sh check-context GPU --checkpoint PATH --output results/context_check.json` 使用原始完整 Future 权重、固定合成图像和固定噪声检查：

1. 重复输入的输出一致。
2. 改变有效上下文动作时输出变化。
3. 改变有效上下文长度时输出变化。
4. 仅修改被 mask 的补齐动作时输出一致。
5. 空上下文和最大上下文输出形状正确且全部有限。

合成观测检查验证上下文计算路径；闭环效果需要另外运行 LIBERO。更新后必须重启原服务，保留旧实验日志，将新结果写入不同输出目录。

2026-11-17 已在 CPU 上使用完整原始 Future checkpoint（step 29999）通过上述检查，严格参数树匹配成功。输出为反归一化后的 10×7 动作，最大绝对差如下：
